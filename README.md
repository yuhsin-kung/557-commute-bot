# 557 通勤平台：東吳通勤達人 LINE Bot

東吳黑客松・流程改善組。幫外雙溪校區學生分散 557 尖峰人潮的 LINE Bot（`@311zktcn`）。

- **技術**：LINE Messaging API + Google Apps Script + Google 試算表，全部免費額度
- **程式**：`bot/` 是備份，**真正在跑的在 Apps Script**，改程式兩邊都要改
- **細節**：每個功能怎麼用、Bot 回什麼、背後怎麼做看 [LINE使用流程.md](LINE使用流程.md)；指令、規則、試算表欄位看 [LINE指令說明.md](LINE指令說明.md)

## 功能

| 選單 | 功能 |
|---|---|
| 出門前提醒 | **🚇 預估到達時間**（傳位置看現在出發幾點到）、**⏰ 幾點出門**（選節次和大樓再傳位置，倒推最晚幾點出門；兩個都把尖峰排隊算進去）、比較所有路線（公車＋YouBike＋計程車共乘）、557 發車前提醒、557 即時動態、降雨查詢、雨天與考試週訂閱提醒 |
| 557 以外的選擇 | 計程車共乘、YouBike 車數、共享雨傘（規劃與 Raingo 合作）、包車調查（規劃中） |
| 公車站牌與排隊禮儀 | 557 最新上車地點、排隊禮儀短片；站牌改了推播給所有好友 |
| 積分與打卡 | 到校打卡（走路進學校、早到、騎車到校）、出校打卡（走路出學校、騎車回士林，放學分流）；走路和早到用定位打兩次卡，騎車傳 YouBike 截圖；每種一天一次、一天最多 3 點，集滿 5 點換 30 元學餐折價券；我的紀錄、全校減碳。規則與防作弊見 [打卡防弊改善.md](打卡防弊改善.md) |
| 學校端 | 每晚 10 點 AI 整理每日報表，寄給德育中心、軍訓室 |

加好友時會自動推送新生須知。

## 設定

**1. 指令碼屬性**（Apps Script → 專案設定）

- 必填：`LINE_CHANNEL_ACCESS_TOKEN`、`TDX_CLIENT_ID`、`TDX_CLIENT_SECRET`、`CWA_API_KEY`、`GEMINI_API_KEY`
- 選填：`REPORT_EMAILS`（報表收件人）、`ETIQUETTE_VIDEO_URL`、`NEWBIE_VIDEO_URL`、`RAINGO_URL`、`CHARTER_FORM_URL`（包車表單）

**2. 在編輯器各執行一次**：`設定晚上提醒排程`、`設定站位檢查排程`、`設定共乘排程`、`設定每日報表排程`、`設定557紀錄排程`

**3. 試算表**：手動匯入 `bot/行事曆.csv`，分頁名稱叫「行事曆」；其他分頁 Bot 會自己建。

**4. LINE 後台**：自動回應關閉、Webhook 開啟。圖文選單用 `design/圖文選單.png`（大型 4 格，跟簡報一樣），四格傳出的文字：`出門前提醒`、`557 以外的選擇`、`公車站牌與排隊`、`積分與打卡`。主要功能「預估到達時間」在出門前提醒的第一顆。改圖：`npm run preview` 後開 http://localhost:4557/menu 按「存成 PNG」

## 改程式

1. 改 `bot/` 裡的檔案，跑 `npm test`
2. 貼到 Apps Script 對應的檔案，存檔
3. **部署 → 管理部署作業 → ✏️ → 新版本**（不要按「新增部署作業」，網址會變）
4. 手機測試，commit

`npm run validate:line` 會檢查卡片格式 LINE 收不收（需要 `keys.env`）。

## 557 監測（電腦上跑）

`tools/557監測.py` 每 15 秒從臺北市公車動態網站記錄 557，整理成 Excel（`data/557監測/`）：每班車的天文館發車時間、到士林國中之前每一站的時間和每段幾分鐘、到士林國中、捷運士林站、東吳的時間，以及到／離士林國中、捷運士林站時的車上人數（綠舒適、黃中等、紅擁擠）；回程另有一張表：在東吳校內停多久、錢穆故居到捷運士林站每站的時間，和到／離錢穆故居、士林站的人數。另外記網站自己的到站預估（士林國中、捷運士林站、錢穆故居），在「網站預估準度」分頁跟實際到站比，當作預測模型要打敗的基準。

雙擊 `tools/開始監測557.bat`，或：

```powershell
uv run tools/557監測.py
```

預設等到 07:00 開始、19:00 結束；`--now --minutes 10` 立刻測試 10 分鐘；`--rebuild 2026-11-25` 用原始紀錄重新產生 Excel；`--slot 5` 把「每 N 分鐘」分頁改成 5 分鐘一格（預設 10，不到 3 班的格子塗灰）。測試：`uv run --with openpyxl python -m unittest discover -s tests -p "test_*.py"`。

**網站人數可能高估**：下車沒刷卡的人不會被減掉。2026/11/25 逐筆看，東吳學生下車大多有刷卡，沒刷卡的主要是士林高商學生（例如中午有一班顯示 90 人，實際最多約 61 人）。所以 Excel：
- 去程：「離開士林站實際約」介在「網站人數 − 到士林國中時已在車上的人」到「網站人數」之間，再以 557 最多 70 人算剩幾個位置
- 回程：實際人數最多就是網站人數，所以寫「至少剩幾個位置」
- 離開士林站那次回報常常還沒算到剛上車的人（跟到站時一樣），這時改用開到福林國小一帶的人數，備註會寫出來
- 到士林國中以前（天文館～行政中心）一次多上超過 15 人的班（多半是士林高商學生），整班人數清掉（同一台車接著的回程也清，沒刷卡的人回程還算在裡面），只留時間，備註寫「人數已清除」

人數是車「離開」那一站後網站回報的車上人數，所以士林站只看得到「上車 − 下車」的淨值；人數怎麼算的網站沒公開，要用現場觀察核對。

## 到校時間預測（v0）

`tools/預測557.py` 用前幾天的監測資料，預測「幾點到士林站（或士林國中），大概幾點到東吳」，07:00–18:30 每一分鐘、空位門檻 5／10／20 各一筆。方法說明在 `到校時間預測.md` 第六節，詳細數據在 `557實測資料.md`。

```powershell
uv run tools/預測557.py predict --target 2026-11-26
```

```powershell
uv run tools/預測557.py evaluate --target 2026-11-26
```

- `predict`：當天資料還沒收之前先跑，結果存在 `預測紀錄/557預測_日期.csv` 並推上 GitHub，證明預測是事先做的。預設用 11/25 和 11/24（11/24 只跑了下午，會自動只用 17 點以後）
- `evaluate`：那天監測跑完後跑，跟實際比、也跟 Bot 現在的算法（557 一律 12 分、尖峰加 10 分）比，成績存在 `預測紀錄/557成績_日期.csv`。也會算「等車用網站即時預估、車程用我們的模型」的成績
- `--train` 指定用哪幾天，`--window` 改車程的滑動時間窗（預設前後 10 分鐘）

## 機器學習模型

`tools/學習557.py` 訓練三個模型（梯度提升樹），用輪流考試（每次留一天當考卷、其他天訓練）跟 v0 統計方法和 Bot 現行算法比，成績存在 `預測紀錄/557機器學習成績_日期.csv`，結果說明在 `到校時間預測.md` 的「機器學習成效」：

- **車程**：士林站到東吳幾分鐘
- **擁擠**：這班離開士林站時車上幾人（提早預測、車快到時加上士林國中人數）
- **車輛位置**：路上每台車現在在哪，幾分鐘後開到士林站（在家提早查）

```powershell
uv run tools/學習557.py
```

**零件模型**（`tools/零件模型557.py`，11/28）：把路線切成一段一段，每段的開車時間、在總站停多久、今天路況都從資料學，再模擬 200 次預測「在家查、N 分鐘後到站牌，幾點到東吳」，還能給範圍。四天考試裡最準（人已經在站牌平均差 2.1 分），成績存在 `預測紀錄/557零件模型成績_日期.csv`：

```powershell
uv run tools/零件模型557.py
```

士林國中上車：`uv run tools/零件模型557.py --direction 國中`，成績存在 `預測紀錄/557國中上車成績_日期.csv`（尖峰國中也會排隊，這個成績假設搭得上第一班）。

回程（東吳 → 捷運士林站）：`uv run tools/零件模型557.py --direction 回程`，成績存在 `預測紀錄/557回程成績_日期.csv`。

回程排隊預測（離開東吳 59 人以上連續才算要排；到士林站＝預測發車＋時段車程）：`uv run tools/回程排隊預測557.py`。

尖峰排隊預測（國中＋捷運站，要等第幾台、每 15 分鐘建議預留幾分）：`uv run tools/尖峰排隊預測557.py`，成績和時段表存在 `預測紀錄/`。

尖峰到校時間範圍（尖峰一律算進等下一台）：`uv run tools/尖峰範圍557.py`，成績存在 `預測紀錄/557尖峰範圍成績_日期.csv`。

士林站排隊模擬（學生到站時前面排幾人、搭得上哪一班）：`uv run tools/排隊模擬557.py`，成績存在 `預測紀錄/557排隊模擬成績_日期.csv`。11/28 試的結果贏不了簡單方法，原因在 `到校時間預測.md`「士林站排隊模擬」。

簡報圖：`uv run tools/畫圖557.py`，存在 `design/簡報圖/`。

測試要加 scikit-learn：`uv run --with openpyxl --with scikit-learn python -m unittest discover -s tests -p "test_*.py"`（沒裝的話模型測試會跳過）。

## 注意

- **金鑰**：只放在 `keys.env`（不上傳）和指令碼屬性。試算表編輯者看得到所有金鑰，不要亂共用
- **LINE 推播**：免費每月 200 則。站位變更會發給所有好友，好友多時很耗額度
- **557 到站紀錄**：`到站紀錄.gs` 每分鐘（06:00–20:30）從臺北市公車動態網站（pda5284.gov.taipei）記錄 557 每台車的到離站、擁擠程度、車上人數，以及網站預估的到站秒數，存在「557動態紀錄」「557預估紀錄」分頁，給到校時間預測用。不用金鑰、不耗 TDX 點數
- **捷運到站牌**（`捷運到站牌.gs`）：學生在 LINE 傳位置（位置訊息，不開外部網頁）→ 最近的捷運站 → Google 地圖走路時間（Apps Script 內建，不用金鑰；每天最多 800 次，超過用距離估）→ 士林站時刻表 → 加 5 分鐘到 557 站牌。第一次執行會要求授權。定位不存
- **測試模式、預估紀錄**（`到校預估.gs`）：傳 `測試時間 週三 09:05` 假日也能試；每次預估寫進「預估紀錄」分頁（不記使用者、位置），平常日用 `uv run tools/對答案預估紀錄557.py` 跟監測資料對答案
- **到校預估**（`到校預估.gs`＋`預測表557.gs`）：到站牌時間 → 幾點到東吳，尖峰給範圍、兩個站牌推薦比較早的。`預測表557.gs` 是 `uv run tools/匯出Bot預測表557.py` 產生的，不要手改
- **TDX**：有每秒次數限制，不要大量下載歷史資料（曾因此被停權）
- **估計值**：車程、步行時間、碳排係數還沒實測，數字在 `比較器.gs`、`積分.gs`
