# 557 通勤平台：東吳通勤達人 LINE Bot

東吳大學外雙溪校區的通勤小幫手。557 是從捷運士林站到外雙溪校區最常用、也最擠的公車。尖峰時段 557 的班次沒有比較多（實測尖峰平均 7.9 分鐘一班、離峰 10.2 分鐘），加開班次又不是學生能決定的，所以這個 LINE Bot 改從「讓人潮分散開來」下手：比較所有到校方式、提醒提早出門、湊計程車共乘、用集點鼓勵早到和步行，並把每天的紀錄整理成報表給學校。

- **LINE 官方帳號**：東吳通勤達人 `@311zktcn`
- **黑客松**：東吳黑客松・流程改善組。初審書面簡報已於 2026/10/30 繳交
- **技術**：LINE Messaging API + Google Apps Script + Google 試算表，不用架伺服器，全部在免費額度內

> **這個 repo 是備份，真正在跑的程式在 Apps Script 裡。** 改程式要兩邊都改，見[修改程式後怎麼更新](#修改程式後怎麼更新)。

## Bot 聽得懂什麼

每個功能都有按鈕，學生不用記指令；按鈕都做在訊息裡（不用輸入框上面那排「快速回覆」），每張卡片最下面有「回選單」。打字也可以：

| 想做什麼 | 可以傳 |
|---|---|
| 主選單 | `選單`、`功能`、`說明`、`menu` |
| 比較路線 | `比較所有路線`；`8點在D棟上課`、`明天早八 H棟`、`第三節在一教`（規則先判斷，看不懂才問 Gemini） |
| 從其他捷運站出發 | `我從劍南路站出發，第二節在二教`、`我住大直，早八圖書館` |
| 557 | `557`、`557 即時動態`；回程：`回家`、`下課` |
| 天氣、站牌 | `明天會下雨嗎`、`557 在哪裡搭`、`站牌在哪` |
| 其他 | `共乘`、`YouBike`、`打卡`、`騎車到校`、`我的紀錄`、`兌換折價券`、`我的折價券`、`新生須知`、`包車`、`共享雨傘` |

看不懂的句子一律回選單。完整規則見 [LINE指令說明.md](LINE指令說明.md)。

### 比較器的核心發現

從**捷運士林站(中正)** 上車，有 13 條公車跟 557 **走一模一樣的 6 站**到「東吳大學(錢穆故居)」站：

> 255、255區、304承德、304重慶、680、683、683預、957、北環幹線、紅30、小18、小19、市民小巴1

557、300 會再多開一站進校園（「東吳大學」站），通勤30 是直達。所以在士林站**不用死等 557**，哪班先來搭哪班，到錢穆故居站下車走進學校就好。

### 2. 金鑰和設定（指令碼屬性）

金鑰**只放兩個地方**：本機的 `keys.env`（不會上傳 GitHub），和 **Apps Script → ⚙️ 專案設定 → 指令碼屬性**（Bot 實際用的是這裡）。

> ⚠️ **任何有試算表「編輯者」權限的人都看得到所有金鑰**。試算表只共用給隊員；只需要看數據的人給「檢視者」；有人退出就移出共用，並重新產生金鑰。

**必填**（名稱要一模一樣）：

| 屬性 | 用途 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 回覆、推播 |
| `TDX_CLIENT_ID`、`TDX_CLIENT_SECRET` | 公車即時到站 |
| `CWA_API_KEY` | 降雨機率 |
| `GEMINI_API_KEY` | 看懂學生打的字、讀 YouBike 截圖、摘要公告和報表。沒有也能跑，只是騎車截圖驗證不能用 |

**選填**（有設定才會出現對應的功能）：

| 屬性 | 設了之後 |
|---|---|
| `REPORT_EMAILS` | 每日報表寄給這些信箱（逗號分隔）；沒設只存在試算表 |
| `ETIQUETTE_VIDEO_URL` | 排隊禮儀卡片點下去打開短片 |
| `NEWBIE_VIDEO_URL` | 新生須知多一行教學短片連結 |
| `RAINGO_URL` | 共享雨傘卡片多一顆「看借用方式」 |
| `CHARTER_FORM_URL` | 學生包車卡片顯示「表單開放中」和填表按鈕；統計截止後刪掉 |
| `COUPON_IMAGE_URL` | 學餐折價券頁面最上面的橫幅圖 |
| `SURVEY_A`、`SURVEY_B`、`SURVEY_C` | 問卷入口（`部署網址?page=survey`）依年級平均分到三個版本 |

### 3. 打開 Apps Script

用隊伍 Gmail 打開「**557 通勤平台**」試算表 → **擴充功能 → Apps Script**。`bot/` 裡的 18 個 `.gs` 檔都要在裡面（`Code.gs` 在 Apps Script 叫 `程式碼.gs`）。

### 4. 排程：在編輯器各執行一次

| 函式 | 設定什麼 |
|---|---|
| `設定晚上提醒排程` | 每晚 9 點：雨天、考試週提醒 |
| `設定站位檢查排程` | 每 6 小時檢查德育中心公告（也會記下現在的頁面當比對基準） |
| `設定共乘排程` | 每分鐘：共乘成團、沒出現扣分、出發提醒、**557 發車提醒** |
| `設定每日報表排程` | 每晚 10 點：每日報表 |

重複執行不會重複設定。

### 5. LINE 後台

- 官方帳號的「**自動回應訊息**」關閉、「**Webhook**」開啟
- 圖文選單：版型選**大型、4 格**，背景圖 `design/圖文選單.png`，每一格的動作選「文字」：

| 位置 | 文字（要一模一樣） |
|---|---|
| 左上 | `出門前提醒` |
| 右上 | `557 以外的選擇` |
| 左下 | `公車站牌與排隊禮儀`（舊的 `公車站牌與排隊` 也認得） |
| 右下 | `積分與打卡` |

### 6. 試算表的分頁

Bot 會自己建立需要的分頁（訊息紀錄、共乘、積分、折價券、報表…），欄位見 [LINE指令說明.md](LINE指令說明.md) 第 6 節。只有「**行事曆**」要手動匯入 `bot/行事曆.csv`：**檔案 → 匯入 → 上傳 → 插入新工作表**，分頁名稱一定要叫「行事曆」（考試週判斷用）。

## 修改程式後怎麼更新

1. 改本機 `bot/` 裡的檔案，跑 `npm test` 確認全部通過
2. 到 Apps Script 打開對應的檔案，**`Ctrl+A` 全選 → 刪光 → 貼上新的**；新檔案按「＋ → 指令碼」新增
3. `Ctrl+S` 存檔，確認「尚未儲存變更」消失
4. **部署 → 管理部署作業 → ✏️ 編輯 → 版本選「新版本」→ 部署**
5. 用手機傳訊息給 Bot 確認
6. commit 到 GitHub

> ⚠️ 第 4 步一定要做，不然 LINE 用的還是舊版程式。
> ⚠️ 不要按「**新增部署作業**」，那會產生新網址，LINE 的 Webhook 就要重設。

```bash
npm run preview
```

打開 http://localhost:4557 預覽等車室、打卡頁、所有卡片（`/cards`）和圖文選單（`/menu`）。

```bash
npm run validate:line
```

把每一種卡片送到 LINE 的驗證介面，**只檢查格式、不會發送訊息**（需要 `keys.env`）。卡片格式有一點不對，LINE 就整則不收，所以改了任何回覆都要跑一次。

### 在 Apps Script 裡測

| 函式 | 做什麼 |
|---|---|
| `測試` | 印出 557 到站、降雨機率 |
| `測試比較器` | 用範例句子問比較器 |
| `測試晚上提醒` | 只印出來、不發送：未來幾天會不會提醒、訂閱人數、剩餘額度 |
| `測試站位變更` | 不推播：假裝站牌搬家、只改排版，看判斷結果 |
| `測試每日報表` | 不寄信、不存檔，印出今天的報表 |
| `測試YouBike`、`測試問卷入口` | 印出資料，確認抓得到 |
| `試發給訂閱者` | ⚠️ 真的會發、會用掉額度。要先把指令碼屬性 `ALLOW_TEST_PUSH` 設成 `1` |
| `建立計數表單`、`建立通勤問卷`、`建立回饋問卷` | 建立 Google 表單，各只會建一次 |

> 不要直接執行 `doPost`，它是等 LINE 傳訊息進來才用的，直接執行一定會出錯。

## ⚠️ 注意事項（一定要看）

### 🔑 金鑰

- **`keys.env` 絕對不能上傳 GitHub、不能傳到群組、不能截圖**。`git add` 前看一下 `git status`
- 金鑰外流了就到該平台**重新產生**，再更新 `keys.env` 和指令碼屬性

### 💬 LINE 推播額度

**免費方案每月只能主動推播 200 則**，以人次計算（50 人收一次＝50 則）。「回覆」不限次數。會用到推播的地方：

| 推播 | 一次用幾則 |
|---|---|
| 雨天、考試週提醒 | 訂閱人數 |
| **站位變更** | **所有好友人數**（不用訂閱，站牌真的改了才發） |
| 557 發車提醒 | 每個設定提醒的人 1 則 |
| 共乘預約：有人加入或取消、出發前提醒 | 這班的人數 |

共乘和發車提醒在剩不到 30 則時自動停發，把額度留給雨天提醒。好友超過 200 人時，一次站位變更就會用光當月額度，要考慮付費方案。

### 🚌 TDX

- 有**每秒呼叫次數限制**（429）。比較器一次只查一個站牌的所有路線並快取 30 秒；發車提醒只在推播的那一刻查一次
- ⚠️ **不要大量下載歷史資料**，之前曾經因為用量過大被暫停帳號
- TDX 沒有 557 的站間行駛時間，車程是估計值（見下面）

### 🌐 公開網頁呼叫得到的函式

等車室、打卡頁、折價券頁、問卷入口是公開網頁。Apps Script 的網頁可以呼叫專案裡**任何名稱不是底線結尾的函式**。所以：內部用的函式名稱一律用底線結尾（例如 `cpTick_`）；一定要公開的（排程、手動執行的）要擋住重複執行。`tests/公開網頁.test.js` 有一張公開函式清單，新增公開函式沒加進去測試就會失敗。

Apps Script 讀不到 HTTP header，**沒辦法驗證 LINE 的簽章**，原型可以接受，正式上線前要改成有伺服器的架構。

### 🛠 Apps Script 常見問題

- **打不開 Apps Script**（網址有 `authuser=2`）：同時登入多個 Google 帳號造成的，用無痕視窗只登入隊伍帳號
- **「這個應用程式未經 Google 驗證」**：自己寫的程式都會出現，進階 → 前往 → 允許
- **存不了**：某個檔案有語法錯誤，最常見是複製時漏了第一行 `/**`
- **Gemini 免費版每分鐘只能叫幾次**，所以比較器先用規則，看不懂才叫 Gemini

### 🔒 隱私

- 只收集必要的：LINE 使用者 ID（看不出是誰）、訊息內容、打卡和選擇紀錄
- 打卡用定位，但**只記打卡點名稱和距離，不記經緯度**
- 騎車截圖、照片只拿來讀資料，不存檔
- 共乘等車室會顯示同團的 LINE 暱稱
